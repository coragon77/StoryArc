## Part B: the taken names

**`lib/knowledge/names.js`**

- `nameWords`: a single letter is never a name word (after the trailing
  period is stripped); in a name of several words, a lowercase word is no
  name word (particles are already dropped; now every lowercase word in a
  multi-word name); a name or alias that starts with a lowercase `the`, `a`
  or `an` gives no words.
- `listTakenNames`: a hyphen piece goes through the same letter and
  single-letter tests as a word (`HH-904` → `HH`; `07-A` → nothing).
- `TITLE_WORDS`: add `nurse`.
- The doc comments of both functions say the new rules.

**`prompts/extract-knowledge.txt`**, NEW CHARACTERS: one sentence. A
character the messages give no name is listed under a short lowercase
description starting with "the" ("the woman with the umbrella"), never a
made-up name or a Title Case label ("Unknown Caller"); a name learned later
goes under newNames.

**Tests** (`tests/test-knowledge-names.js` or the file that tests
`nameWords` today): the measured inputs with hand-written expected words:
`HH-904` → `HH`; `ID #07-A` → `ID`; `Mara K.` → `Mara`; `M. G.` → none;
`Woman with Umbrella` → `Woman`, `Umbrella`; `the Obsidian Lounge hostess`
→ none; `Nurse Cruz` → `Cruz`; `zoe` → `zoe`; `Marissa Vance-Chen` →
unchanged. `listSharedNames` (through the extraction apply) no longer flags

## Part A1: one list of what goes to the narrator

**New file `lib/injection/narrator-prompts.js`** (two callers: index.js and
the view):

- `listStoryArcPrompts()` → `[{ key, label, text, position, depth, role }]`
  in prompt order: plan, knowledge, names, signals. Gates as today:
  `isEnabled()`, active arcs for plan and signals, `isKnowledgeTrackerEnabled()`
  for knowledge and names. Positions, depths, roles exactly as
  `injectStoryArcPrompts` and `injectKnowledgeBlock` pass them now.
- **index.js** `injectStoryArcPrompts`: a loop over the list calling
  `setExtensionPrompt(key, text, position, depth, false, role)`. Comments
  that explain placement (signals near the generation point, knowledge at
  depth 1) move to the list.
- **ledger.js** `injectKnowledgeBlock` goes; its imports of
  `setExtensionPrompt` and the prompt types go if nothing else uses them.
- **Tests:** the `injectKnowledgeBlock` cases in
  `test-knowledge-inject.js`, `test-knowledge-appearance.js` and
  `test-knowledge-details-switch.js` call `injectStoryArcPrompts` (index.js)
  or `listStoryArcPrompts` instead, same assertions. A new test pins the
  full `setExtensionPrompt` argument lists for a fixture with arcs and the
  tracker on, and for Story Arc off (every key set to `''`).

**`lib/injection/builder.js`:** export `TRIMMABLE_LIST_HEADER` and the
opening phrases of the BEAT CHECK and PLANT CHECK lines as constants
(`buildSignalDirective` uses them, the mask uses them).

## Part A2: Last sent

**`lib/injection/narrator-prompts.js`** also holds the snapshot:

- `noteGenerationType(type, dryRun)`: called from `onGenerationStarted`;
  keeps the type of the last non-dry generation in a module variable.
- `saveLastSent(outgoingChat)`: called from `onChatCompletionPromptReady`
  for every non-dry request, after stamping. Returns without saving for a
  `quiet` type, or when no non-empty Story Arc prompt (read from ST's
  `extension_prompts` registry under our keys) appears in any entry of the
  outgoing array. Otherwise writes
  `chat_metadata.story_arc.lastSent = { replyIndex, newestMessageIndex, type, savedAt, parts: [{ key, text, position, depth }], stamp: { messageIndex, text } | null }`.
  `replyIndex` is `chat.length - 1` for `swipe` and `continue`, else
  `chat.length`. The stamp is read from the outgoing array: the first line
  of the newest user entry that starts with the stamp prefix (a constant
  exported from stamping.js, used by `buildStamp`).
- `dropLastSentPastEnd(chatLength)`: called from `onChatChanged`; drops a
  snapshot whose `replyIndex` is past the chat's end (a branch).
- **index.js** `onChatCompletionPromptReady`: dry run → return; Story Arc
  off → return; stamp when arcs are active (as now); then `saveLastSent`.
- **`tests/mocks/st-mocks.js`:** export `extension_prompts` (an object the
  `setExtensionPrompt` mock writes into, as ST's does).
- **Tests:** dry run, quiet type, an outgoing array without Story Arc text,
  and a deletion save nothing; a normal send saves `replyIndex =
  chat.length` with the registry texts; a swipe saves `chat.length - 1`; the
  stamp is read from the array; a branch drops a snapshot past its end.

## Part A3: the view

**New file `lib/ui/sent-view.js`**, `showSentView()`, a large ST popup in
the Arc Manager's grammar, layout C of the mockup:

- Head, note line, strip (left, 280px), reader (right), status bar, as the
  design note. Next request: `listStoryArcPrompts()` plus the stamp from
  `buildStamp(selectPacingClock(arcs), index)`. Last sent: the snapshot.
- `maskSpoilerLines(partKey, text, arcs, ledger)` lives here (one caller),
  exported for the tests: by place (the builder's exported headers and
  phrases) and by content (every line of every secret content, trigger
  condition and action, clue and target, and fulfillment of the active arcs;
  lines shorter than 12 characters are not used for the content match, so
  a short line cannot hide unrelated text).
- Planned holders: the names of characters that hold any fact only as
  `plan`; a knowledge line with "(shared only with …" that names one is
  hidden.
- Reveal: session-only, off on open. Default mode: Last sent when a snapshot
  exists, else Next request with Last sent disabled and its reason as the
  tooltip.
- Strip: keyboard (Up/Down between blocks), `aria-pressed` on the chosen
  block.
- Tokens: `estimateTokens`; the plan's line names the chat's
  `injectionBudget`.
- Pure builders (`buildSentViewContent(view)`, the strip, the reader) take
  plain data, so tests render them without ST.

**`lib/css/sent-view.css`** (imported in `style.css`): only what the Arc
Manager's CSS lacks (strip, blocks, gaps, reader well, placeholder, change
mark), from the mockup, ST theme variables only.

**Entry points:** a "What the narrator gets" button in the drawer's action
row (`settings-panel.js`) and in the wand popup (`wand-menu.js`, closes the
wand popup first, like Manage). Icon `fa-solid fa-layer-group`.

**Tests** (`tests/test-ui-sent-view.js`):

- `maskSpoilerLines`, the outcome: a fixture arc with secrets, triggers,
  clues and fulfillments, one item with a newline and one with a blank
  line inside; no spoiler text appears in the masked rendering; every one
  appears with Reveal on; premise, world facts and pressure appear in both.
- The planned-holder line is hidden, the others are not.
- The view content: five blocks in prompt order with their token counts;
  the state texts (Story Arc off, nothing sent, no snapshot); the change
  mark in Next request on a line not in the snapshot.
- Wand menu and settings panel: the new button exists (extend the existing
  UI tests).
